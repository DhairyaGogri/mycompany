Delivery controls

Practical controls for reliable digital delivery.

This page describes the delivery principles built into our operating approach. It is not a declaration of third-party certification. Formal certificates, insurance schedules and signed policies can be supplied separately where required by a procurement process.

Accessibility

We use semantic HTML, keyboard-accessible controls, visible focus states, logical headings, readable contrast and responsive layouts as baseline practices. Accessibility is checked during QA rather than treated as an end-stage add-on.

Information security

We apply least-necessary access, version control, controlled configuration and careful handling of client information. Secrets should be stored outside source code and production access should be limited to authorised delivery personnel.

Data protection

Projects are designed around data minimisation, purpose limitation, controlled access and clear retention expectations. Processing arrangements and contractual roles should be agreed with the buyer where personal data is involved.

Quality assurance

We use requirement checks, code review where appropriate, browser/device testing, broken-link checks and documented acceptance criteria before handover.

Change control

Changes are logged, assessed for effect on scope/time/cost and agreed before implementation. Releases should be versioned so that changes are traceable.

Business continuity

Source code, documentation and configuration should remain reproducible, with clear ownership and handover notes so delivery does not depend on undocumented personal knowledge.

Social value and responsible delivery

For public-sector work, we intend to prioritise inclusive digital access, practical knowledge transfer and opportunities for local or early-career contribution where project circumstances allow. Any scored social-value commitments should be made specific in the tender response and contract plan rather than implied by generic website wording.
